AWS & Cloud Computing — Interactive Q&A (Basics)

Quick answers for beginners: cloud concepts, AWS building blocks, security, networking, and scalability.

What is Cloud Computing?

Cloud computing means renting IT resources (compute, storage, databases, networking, analytics, etc.) over the internet instead of buying and maintaining physical servers yourself. You can scale up/down quickly and pay only for what you use.

What is AWS?

AWS (Amazon Web Services) is a cloud platform that provides on-demand services like virtual servers, storage, databases, networking, security, and more—so teams can build and run apps without managing physical infrastructure.

What is the AWS Shared Responsibility Model?

Security is shared: AWS handles security of the cloud (data centers, hardware, core infrastructure), while customers handle security in the cloud (their data, identity/permissions, configurations, and applications). For EC2, customers manage the guest OS patches and security group rules; for services like S3, customers still manage data access and permissions.

Tip: Most real cloud incidents come from customer misconfiguration—review IAM policies, encryption, and network exposure regularly.

What are AWS Regions and Availability Zones (AZs)?

A Region is a geographic area (e.g., US East). Each Region contains multiple Availability Zones—isolated locations (one or more data centers) with independent power/networking. Best practice is to run workloads across multiple AZs so your app stays available even if one AZ has issues.

What is a VPC (Virtual Private Cloud)?

A VPC is your own isolated virtual network inside AWS where you launch resources (like EC2). You control IP ranges, subnets, routing, and network access—similar to a private data center network.

What is a Subnet? Why do we use it?

A subnet is a slice of your VPC’s IP range placed in a specific Availability Zone. You use subnets to separate resources by purpose and risk: public subnets (internet-facing) and private subnets (internal services).

What is a Route Table?

A route table decides where network traffic goes from a subnet. Example: a route that sends 0.0.0.0/0 to an Internet Gateway enables outbound internet access for that subnet.

What is an Internet Gateway (IGW)?

An Internet Gateway connects your VPC to the public internet. Typically, public subnets route internet-bound traffic to the IGW so resources can be reachable (when security rules allow it).

What is a NAT Gateway? When do I need it?

A NAT Gateway lets resources in a private subnet access the internet for outbound needs (updates, package downloads) without allowing inbound internet connections to those private resources.

What is Amazon EC2?

EC2 is a service that provides virtual servers (“instances”) in the cloud. You choose CPU/RAM capacity, an OS image (AMI), storage, and networking—then run your application like on a normal server.

What is Amazon S3?

S3 is object storage for files such as images, videos, backups, logs, and datasets. Data is stored in buckets and accessed via policies/permissions.

What is IAM, and why is it important?

IAM (Identity and Access Management) controls who can access AWS and what they can do. Core pieces are users, groups, roles, and policies. Best practice is “least privilege” and using MFA for sensitive accounts.

What is a Load Balancer in AWS?

A Load Balancer distributes incoming traffic across multiple EC2 instances so apps remain fast and available. If one instance fails, traffic is redirected to healthy instances—improving uptime and scalability.

Common types include Application Load Balancer (ALB) for HTTP/HTTPS and advanced routing, and Network Load Balancer (NLB) for high-performance TCP/UDP.

What is Auto Scaling (ASG) and why do we use it?

Auto Scaling automatically adjusts the number of EC2 instances based on demand (scale out/in). It helps maintain performance during peak traffic and reduces cost during low usage. It can also replace unhealthy instances automatically.

What is the AWS Well-Architected Framework?

The AWS Well-Architected Framework is guidance for designing and running cloud systems using six pillars: Operational Excellence, Security, Reliability, Performance Efficiency, Cost Optimization, and Sustainability.

What’s a simple beginner path to learn AWS?
  1. Start with IAM (users/roles/policies) and billing basics.
  2. Learn networking: VPC → subnets → route tables → IGW/NAT.
  3. Compute: EC2 + storage options.
  4. Storage: S3 basics + access policies.
  5. High availability: Load Balancer + Auto Scaling across AZs.
  6. Security & best practices: Shared Responsibility + Well-Architected pillars.
